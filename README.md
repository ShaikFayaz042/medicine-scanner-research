# Medicine Scanner Research

Research and prototype tooling for collecting, extracting, classifying, and searching medicine-safety and regulatory information published by CDSCO and IPC/PvPI.

The repository currently contains two related parts:

1. A reproducible document research pipeline covering CDSCO Alerts, FDC notifications, public notices, Gazette notifications, banned drugs, NSQ/spurious records, and IPC/PvPI safety alerts.
2. A FastAPI-based CDSCO Alerts monitor that stores discovered documents in PostgreSQL, downloads PDFs, serves a small browser UI, and can poll on a schedule.

## Current Status

The research dataset is frozen at `structured_raw` v0.1.0:

- 176 documents
- 7,557 extracted records
- 11 structured document types
- Unified indexes in `structured_raw/_master.json`, `structured_raw/_all_documents.json`, and `structured_raw/_all_records.ndjson`
- Validation reports and checksums generated by `scripts/finalize.py`

These are raw extractions. Dates, names, and values are intentionally preserved as they appeared in the source documents; normalization and product matching are future work.

## Sources

| Source | Collection method | Main value |
| --- | --- | --- |
| CDSCO Alerts | HTML table and wrapped PDF links | Regulatory safety and enforcement documents |
| CDSCO FDC | HTML tables and PDFs | Fixed-dose combination notifications |
| CDSCO Public Notices | HTML tables and PDFs | Public regulatory notices |
| CDSCO Gazette | HTML tables and PDFs | Legal notifications |
| CDSCO Banned Drugs | Iframe PDF and SHA-256 tracking | Prohibition list |
| CDSCO NSQ and Spurious | Public JSON endpoints | Batch-level quality and suspicion records |
| IPC/PvPI | Static pages and direct PDFs | Drug safety alerts and adverse reactions |

The research found that the sources can be collected with ordinary HTTP requests. Browser automation, proxies, and Scrapy are not currently required.

## Setup

Create a virtual environment and install the dependencies:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

The extraction tooling may also require Tesseract OCR to be installed separately for scanned PDFs. `pymupdf-layout`, `pymupdf4llm`, RapidOCR, and Pillow are included for the available extraction paths.

## Research Pipeline

Run commands from the repository root. The numbered downloaders correspond to the source inventory in `cdsco-downloader/`:

```powershell
python cdsco-downloader/01_download_cdsco_alerts.py
python cdsco-downloader/02_download_cdsco_fdc.py
python cdsco-downloader/03_download_cdsco_public_notices.py
python cdsco-downloader/04_download_cdsco_gazette.py
python cdsco-downloader/05_download_cdsco_banned_drugs.py
python cdsco-downloader/06_download_ipc_pvpi.py
python cdsco-downloader/07_fetch_cdsco_nsq_json.py
```

Then analyze and extract the downloaded material. The extraction scripts support narrower runs; use `--help` for the current options.

```powershell
python cdsco-downloader/analyze_pdfs.py
python raw_extraction/extract_text.py
python raw_extraction/extract_ocr.py
python raw_extraction/analyze_extraction.py
```

Classify PDFs and parse the source-specific records with the scripts in `scripts/`. The exact parser to run depends on the source and classification result. The final dataset steps are:

```powershell
python scripts/validate_records.py
python scripts/finalize.py --version 0.1.0
python scripts/export_csv.py
```

`finalize.py` creates the unified manifests, validation reports, version metadata, and the streamable NDJSON export. `export_csv.py` creates one flat CSV per structured type and exports NSQ API JSON to CSV.

## Running the CDSCO Monitor

The monitor uses PostgreSQL. Create a database named `cdsco_monitor`, then configure the connection before starting the app. The supported environment variables are `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, and `DB_PASSWORD`.

```powershell
$env:DB_HOST = "localhost"
$env:DB_PORT = "5432"
$env:DB_NAME = "cdsco_monitor"
$env:DB_USER = "postgres"
$env:DB_PASSWORD = "<your-password>"

python -m app.init_db
python -m app.seed
uvicorn app.main:app --reload
```

Open `http://127.0.0.1:8000/`. Useful endpoints include:

- `GET /health` - health check
- `GET /api/documents` - downloaded/discovered documents
- `GET /api/documents/{document_id}` - one document
- `POST /api/scrape-now?limit=20` - trigger a scrape and download run
- `GET /api/scheduler` and `PUT /api/scheduler` - inspect or update scheduling
- `GET /static-pdf/{document_id}.pdf` - serve a local PDF inline

`app.seed` is a demonstration seed: it inserts and downloads two of the six fetched alerts, reserving the newest four for the scheduler demo. It is not a production ingestion command.

## Data and Legal Handling

The outputs are research data and should retain a source URL, extraction method, and original wording wherever possible. In particular:

- An NSQ or spurious entry is not automatically proof that a product is unsafe or counterfeit.
- Spurious records may be under investigation and must be presented with their verbatim remarks and source context.
- Banned-drug entries can have different legal states, including quashed, stayed, or revoked-with-conditions items.
- A production schema and UI should carry an explicit `legal_status` instead of presenting every record as an authoritative prohibition.

## Next Steps

1. Replace the app's demonstration seed and hard-coded scheduling assumptions with a real incremental ingestion workflow for all seven sources.
2. Add a normalized schema for products, ingredients, manufacturers, batches, legal status, source documents, and provenance while retaining the raw records unchanged.
3. Implement source-aware deduplication and update detection: CDSCO document IDs, NSQ product/batch/manufacturer tuples, and SHA-256 or filename tracking where no stable ID exists.
4. Add search and matching across NSQ, spurious, banned-drug, and PvPI records, with clear uncertainty and legal-status labels in the UI.
5. Move database credentials out of code defaults, add migrations, and add automated tests for scrapers, parsers, validation contracts, and scheduler behavior.
6. Add an automated refresh job with rate limits, retry/backoff, change reports, and checksums so dataset versions can be reproduced.
7. Complete the remaining research clean-up items documented in `websites/README.md`, especially PvPI year-link coverage and banned-drug legal-status normalization.
